# Google Search Console: Guia Completo Para SEO

Google Search Console (GSC) é a ferramenta gratuita do Google que fornece dados diretos sobre como o buscador vê, rastreia, indexa e ranqueia o seu site. É a ferramenta mais importante de SEO — não porque é a mais completa, mas porque é a única fonte de dados reais do Google. Enquanto ferramentas como SEMrush e Ahrefs trabalham com estimativas e amostras, o Search Console mostra exatamente quais queries geraram impressões e cliques, quais páginas estão (ou não) no índice, quais problemas técnicos o Google encontrou e como os Core Web Vitals do site estão performando.

Nenhuma operação de SEO pode funcionar sem o Google Search Console. Ele é o ponto de partida do diagnóstico, a base do monitoramento contínuo e a fonte primária de dados para decisões de otimização. Ignorar o GSC é como operar no escuro — tomando decisões baseadas em estimativas de terceiros quando os dados reais estão disponíveis gratuitamente.

## 🔧 O Que É o Google Search Console

O Google Search Console é a interface oficial do Google para webmasters e profissionais de SEO. Lançado originalmente como "Google Webmaster Tools" em 2006, foi reformulado e renomeado em 2015. A plataforma fornece relatórios, ferramentas de diagnóstico e alertas que permitem entender como o Google interage com o site — desde o rastreamento inicial até a exibição nos resultados de busca.

### A Ferramenta Gratuita do Google Para Webmasters

O GSC é 100% gratuito e acessível a qualquer proprietário de site. Fornece dados que nenhuma ferramenta paga consegue replicar com precisão: queries reais dos usuários (não estimativas), cliques reais (não projeções), status de indexação direto do Google (não inferências de crawlers externos), e alertas de problemas técnicos identificados pelo próprio Googlebot.

Os principais módulos do Search Console incluem: Relatório de Desempenho (queries, cliques, impressões, CTR, posições), Relatório de Indexação (cobertura, erros, páginas válidas), Inspeção de URL (status individual de qualquer página), Core Web Vitals (performance de experiência do usuário), Sitemaps (submissão e monitoramento), Links (perfil de links internos e externos) e Ações Manuais (penalizações aplicadas pelo Google).

Para quem está começando em SEO, o GSC é a primeira ferramenta a configurar — antes de qualquer investimento em ferramentas pagas. Para profissionais experientes, é a fonte de verdade que valida (ou contradiz) os dados de outras plataformas.

### Como Configurar e Verificar Seu Site

A configuração do GSC exige a verificação de propriedade do site. O Google oferece múltiplos métodos de verificação: registro DNS (recomendado para propriedades de domínio), tag HTML no cabeçalho do site, upload de arquivo HTML na raiz do servidor, tag do Google Analytics (se já estiver instalado) ou tag do Google Tag Manager.

A recomendação é verificar o site como "Propriedade de domínio" (usando DNS), que cobre todas as variações de URL (com e sem www, HTTP e HTTPS, subdomínios). Alternativamente, propriedades de "Prefixo de URL" cobrem apenas a variação exata configurada — útil para monitorar seções específicas do site separadamente.

Após a verificação, o GSC começa a coletar dados. Os dados de desempenho levam algumas horas a poucos dias para aparecer. Dados de indexação e Core Web Vitals podem levar alguns dias a semanas para serem totalmente populados. A configuração correta desde o início garante que nenhum dado seja perdido — quanto antes o GSC for ativado, mais histórico estará disponível para análise.

## 📊 Relatório de Desempenho

O Relatório de Desempenho é o módulo mais utilizado do Search Console. Mostra como o site performa nos resultados de busca do Google: quais queries geram impressões, quantos cliques o site recebe, qual a posição média e qual a taxa de cliques (CTR) para cada query e página.

### Cliques, Impressões, CTR e Posição Média

As quatro métricas fundamentais do relatório são complementares. Impressões indicam quantas vezes o site apareceu nos resultados para uma query — visibilidade bruta. Cliques indicam quantas vezes os usuários clicaram no resultado — tráfego real gerado. CTR (Click-Through Rate) é a razão entre cliques e impressões — eficiência do resultado em atrair o clique. Posição média indica a posição média do site nos resultados para cada query — competitividade.

Cada métrica conta uma parte da história. Impressões altas com cliques baixos indicam problema de CTR — o resultado aparece mas não atrai cliques (título ou meta description pouco atrativos). Posição alta (1-3) com CTR baixo pode indicar que AI Overviews ou featured snippets estão roubando cliques acima do resultado orgânico. Impressões crescentes com posição estável indicam que o volume de buscas para aquela query está aumentando — oportunidade de mercado.

### Filtrando por Queries, Páginas, Países e Dispositivos

O poder do Relatório de Desempenho está nos filtros. O relatório permite segmentar por: queries (quais termos os usuários buscaram), páginas (quais URLs receberam impressões e cliques), países (de onde vem o tráfego), dispositivos (mobile, desktop, tablet) e tipo de resultado (web, imagens, vídeo, notícias).

Os cruzamentos entre filtros revelam insights acionáveis. Filtrar por uma página específica e ver as queries que geram impressões mostra para quais termos o Google considera aquela página relevante — incluindo termos que você não tinha como alvo originalmente. Filtrar por mobile vs. desktop pode revelar diferenças significativas de posição — um site que rankeia bem no desktop mas mal no mobile tem um problema técnico a resolver.

Para operações de [SEO técnico](../2-seo-tecnico/2.1-seo-tecnico-guia-completo.md), o filtro por tipo de resultado permite rastrear performance em busca de imagens, vídeos e outros formatos — ampliando a visão além dos resultados web tradicionais.

### Como Identificar Oportunidades de Quick Wins

Quick wins são oportunidades de ganho rápido identificáveis diretamente no Search Console. As mais comuns são keywords onde o site já aparece nas posições 4 a 20 com impressões significativas — termos onde o Google já reconhece a relevância do site, mas que ainda não geram tráfego expressivo por não estarem no Top 3.

Para encontrar quick wins, filtre o relatório por posição média entre 4 e 20, ordene por impressões (decrescente) e identifique as queries com maior volume. Essas são as keywords onde uma otimização direcionada — melhorar o conteúdo da página, ajustar o título e meta description, adicionar links internos, enriquecer com dados estruturados — pode gerar ganho de posições com esforço relativamente baixo.

Outra oportunidade: queries com impressões altas e CTR abaixo da média para a posição. Se uma página está na posição 3 mas tem CTR de 2% (quando a média para posição 3 é 8-12%), o problema está no resultado exibido — título pouco atrativo, meta description genérica ou ausência de rich results. Corrigir o snippet pode dobrar o tráfego sem mudar uma linha de conteúdo.

A TRIWI utiliza a análise de quick wins do Search Console como parte das primeiras ações da [metodologia](../0-triwi/0.3-metodologia-triwi.md) — gerando resultados visíveis nos primeiros meses de trabalho enquanto as estratégias de longo prazo (conteúdo, autoridade) amadurecem.

## 📑 Relatório de Indexação (Cobertura)

O Relatório de Indexação mostra o status de todas as páginas do site no índice do Google: quais estão indexadas (aparecem nos resultados), quais foram excluídas (e por quê) e quais têm erros que impedem a indexação.

### Páginas Indexadas vs. Não Indexadas

O relatório divide as páginas em categorias: "Válidas" (indexadas e funcionando), "Válidas com avisos" (indexadas mas com potenciais problemas), "Excluídas" (não indexadas, por decisão do Google ou do webmaster) e "Erros" (não indexadas por problemas técnicos).

Nem toda página excluída é um problema. Páginas de paginação, parâmetros de filtro, versões duplicadas com canonical — essas exclusões são normais e esperadas. O importante é verificar que as páginas estratégicas (páginas de produto, categorias, artigos-pilar, landing pages) estão na categoria "Válidas". Se uma página estratégica aparece como "Excluída" ou "Erro", há um problema de [crawling e indexação](../2-seo-tecnico/2.5-crawling-e-indexacao-como-garantir-que-o-google-encontre-seu-site.md) a resolver.

### Erros Comuns e Como Resolver

Os erros mais frequentes no relatório de indexação incluem: "Página com redirecionamento" (redirect loops ou cadeias excessivas), "Não encontrada (404)" (página removida ou URL alterada sem redirect), "Erro do servidor (5xx)" (problemas no servidor que impedem o Googlebot de acessar a página), "Bloqueada por robots.txt" (regra no robots.txt impedindo o acesso) e "Rastreada, não indexada" (Google acessou mas decidiu não incluir no índice — geralmente por conteúdo thin ou duplicado).

Cada erro tem uma solução específica. Redirects em cadeia exigem revisão da estrutura de redirecionamentos — cada URL deve apontar diretamente para o destino final, sem intermediários. Erros 404 em páginas com tráfego ou backlinks exigem redirect 301 para a página equivalente. Erros 5xx exigem investigação no servidor. "Rastreada, não indexada" exige revisão do conteúdo — o Google provavelmente considerou que a página não agrega valor suficiente ao índice.

### Inspeção de URL

A ferramenta de Inspeção de URL permite verificar o status individual de qualquer página do site. Mostra: se a URL está no índice do Google, quando foi rastreada pela última vez, qual canonical o Google reconhece, se há dados estruturados válidos, se a página é mobile-friendly e se há problemas de carregamento.

O recurso mais poderoso é o "Teste ao vivo" — que solicita ao Google rastrear a página naquele momento e retorna o resultado atualizado. Útil após implementar correções técnicas para verificar se o problema foi resolvido antes de esperar o próximo rastreamento automático.

A Inspeção de URL também permite "Solicitar indexação" — pedindo ao Google para priorizar o rastreamento e indexação de uma URL específica. Útil para páginas recém-publicadas ou recém-corrigidas que precisam aparecer nos resultados rapidamente.

## ⚡ Core Web Vitals no Search Console

O relatório de [Core Web Vitals](../2-seo-tecnico/2.2-core-web-vitals-performance-que-impacta-rankeamento.md) no Search Console mostra a performance de experiência do usuário do site usando dados reais de campo (CrUX — Chrome User Experience Report). Diferente de testes de laboratório (Lighthouse, PageSpeed Insights), esses dados vêm de usuários reais navegando no site.

### Interpretando os Relatórios de CWV

O relatório classifica as URLs em três categorias: "Bom" (dentro dos limiares recomendados), "Precisa melhorar" (borderline) e "Ruim" (fora dos limiares). As três métricas avaliadas são: LCP (Largest Contentful Paint — tempo de carregamento do maior elemento visível), INP (Interaction to Next Paint — responsividade a interações do usuário) e CLS (Cumulative Layout Shift — estabilidade visual da página).

Os limiares são: LCP bom abaixo de 2,5 segundos, INP bom abaixo de 200 milissegundos, CLS bom abaixo de 0,1. URLs que não atingem esses limiares estão potencialmente perdendo posições para concorrentes com melhor performance — Core Web Vitals são fatores de rankeamento confirmados pelo Google.

O relatório agrupa URLs por padrão — se várias páginas compartilham o mesmo template (ex: páginas de produto em e-commerce), o GSC agrupa e reporta o status do grupo. Isso permite identificar rapidamente quais templates precisam de otimização técnica — corrigir o template resolve o problema para todas as URLs do grupo simultaneamente.

### Mobile vs. Desktop

O Search Console separa os relatórios de Core Web Vitals entre mobile e desktop — e as diferenças podem ser significativas. Uma página que performa bem no desktop pode ter LCP ruim no mobile (carregamento lento em conexões móveis) ou CLS ruim no mobile (elementos que se deslocam em telas menores).

A prioridade deve ser mobile. O Google utiliza mobile-first indexing — o que significa que a versão mobile do site é a versão primária para indexação e ranqueamento. Se os Core Web Vitals estão ruins no mobile, o impacto no ranking é direto, independentemente da performance desktop.

Na prática, a maioria dos problemas de Core Web Vitals em mobile está relacionada a: imagens não otimizadas (LCP alto), scripts de terceiros bloqueando interatividade (INP alto) e anúncios ou elementos dinâmicos que empurram conteúdo (CLS alto). A TRIWI monitora Core Web Vitals mobile de todos os clientes continuamente — problemas detectados no Search Console são priorizados e corrigidos antes de impactarem o ranking.

## 🗺️ Sitemaps e Remoções

O módulo de Sitemaps permite submeter e monitorar os mapas do site — arquivos XML que listam todas as URLs que você quer que o Google rastreie e indexe. O módulo de Remoções permite solicitar a remoção temporária de URLs dos resultados de busca.

### Submetendo e Monitorando Sitemaps

O sitemap XML é o "mapa" que guia o Googlebot pelo site. Submeter o sitemap no Search Console garante que o Google conheça todas as URLs importantes — especialmente em sites grandes onde nem todas as páginas são alcançáveis por links internos.

No GSC, após submeter o sitemap, o relatório mostra: quantas URLs foram encontradas no sitemap, quantas foram rastreadas, quantas foram indexadas e se há erros de processamento. Uma discrepância grande entre "URLs no sitemap" e "URLs indexadas" indica problemas — o Google está ignorando páginas que você considera importantes, seja por conteúdo duplicado, qualidade insuficiente ou problemas técnicos.

A recomendação é manter o sitemap atualizado automaticamente (a maioria dos CMS faz isso) e verificar periodicamente no GSC se novas URLs estão sendo processadas corretamente. Para sites com milhares de páginas, sitemaps segmentados por seção (blog, produtos, categorias) facilitam o diagnóstico de problemas de indexação por área do site.

### Ferramenta de Remoção — Quando Usar

A ferramenta de Remoção permite solicitar que o Google remova temporariamente uma URL dos resultados de busca (por aproximadamente 6 meses). O uso correto é limitado a situações específicas: páginas com informações confidenciais que foram indexadas por engano, URLs antigas que geram confusão e redirecionamentos que ainda não foram processados pelo Google.

A remoção é temporária — se a página continuar acessível e sem tag noindex, o Google pode reindexá-la após o período de remoção. Para remoções permanentes, a solução correta é remover a página do servidor (retornando 404 ou 410) ou adicionar a meta tag noindex.

Usar a ferramenta de remoção como atalho para "limpar" o índice é um erro comum. Remover páginas que não deveriam ser removidas prejudica a cobertura orgânica. A abordagem correta para páginas de baixa qualidade é [content pruning](../3-seo-de-conteudo/3.7-content-pruning-como-remover-conteudo-para-melhorar-seu-seo.md) — melhorar, consolidar ou redirecionar, não simplesmente remover dos resultados.

## 🔗 Links (Internos e Externos)

O relatório de Links do Search Console mostra o perfil de links do site — tanto os links que outros sites fazem para o seu (externos) quanto a estrutura de links entre as próprias páginas do site (internos).

### Relatório de Links Externos

O relatório de links externos mostra: os domínios que mais linkam para o site (top linking sites), as páginas do site que mais recebem links (top linked pages) e os textos âncora mais utilizados nos links (top linking text). São os dados oficiais do Google sobre o perfil de backlinks do site.

Esses dados complementam as informações de ferramentas como Ahrefs e SEMrush — que têm seus próprios índices de links. O índice do Google não é público e nem completamente refletido no GSC, mas os dados disponíveis mostram os padrões mais relevantes: quais domínios o Google reconhece como fontes de [autoridade](../4-link-building/4.2-autoridade-de-dominio-o-que-e-e-como-construir.md), quais páginas concentram a maior parte dos links e quais textos âncora estão associados ao site.

Para estratégias de [link building](../4-link-building/4.1-link-building-guia-completo-de-construcao-de-autoridade.md), o relatório revela oportunidades: páginas com poucos links mas alto potencial podem ser priorizadas para campanhas de aquisição. Páginas com muitos links podem ter essa autoridade distribuída para páginas estratégicas via links internos.

### Relatório de Links Internos

O relatório de links internos mostra quais páginas do site recebem mais links de outras páginas do mesmo domínio. A estrutura de links internos é um dos sinais mais fortes que o Google usa para entender a hierarquia e a importância relativa das páginas.

Páginas estratégicas (páginas de produto, categorias principais, landing pages de conversão) devem estar entre as mais linkadas internamente. Se uma página importante aparece com poucos links internos no relatório do GSC, há uma oportunidade de otimização: adicionar links internos de páginas relevantes pode melhorar o ranqueamento sem nenhuma ação externa.

O relatório também revela problemas de arquitetura: se páginas irrelevantes (termos de uso, política de privacidade) aparecem como as mais linkadas internamente — porque estão no rodapé de todas as páginas — enquanto páginas estratégicas têm poucos links, a distribuição de autoridade interna está subótima. Ajustar a [arquitetura de links internos](../2-seo-tecnico/2.3-arquitetura-de-site-para-seo.md) é uma das otimizações com melhor relação esforço/retorno em SEO.
